# 参加者向け手順

## 今日のゴール
AIに操作を頼み、自分の担当県の旅行プランをPRで提出します。
チームは教え合う単位です。本人がAIへ依頼し、本人が結果を確認してください。
旅行内容を練り込むより、GitHubで何が起きたかを理解することを優先します。

## 最初の準備
1. GitHubへログインし、運営からの招待を受け入れます。
2. ブラウザで授業用リポジトリを開けるか確認します。
3. おいとま・Codex・Claude Codeなど、使うAIを起動します。
4. チーム内で担当県を決め、READMEから担当ファイルの場所を確認します。

おいとま未導入、認証、Gitの導入で止まったら、チームの支援者に相談してください。

## 1. 手元へ持ってくる
参加者は全員Windowsです。保存先は C:\Users\ユーザー名\momoshita-travel-guide に統一します。ユーザー名は自分のWindowsユーザー名です。

Windows + Rで「%USERPROFILE%」を開くと、保存先の親フォルダを確認できます。momoshita-travel-guideフォルダはcloneで作成されます。

> https://github.com/toukasonjuku/momoshita-travel-guide を、Windowsのホーム直下の C:\Users\ユーザー名\momoshita-travel-guide へcloneして。ユーザー名は実際のWindowsユーザー名を使って。同名フォルダがある場合は上書きせず状態を教えて。ファイルを編集する前にAGENTS.mdと参加者向け手順.mdを読み、担当県を確認して。

確認：手元にファイルがあるか。担当県のファイルを開けるか。

## 2. 作業ブランチで編集する
以下の県名とファイルの場所を、自分の担当に置き換えます。

> 私は香川県を担当します。mainを基に自分の作業用ブランチを作り、四国/香川県.mdの5項目を短く埋めて。他のファイルは変更せず、まだコミットしないで。終わったら差分を見せて。

確認：自分のブランチか。担当県のファイルだけが変わっているか。

## 3. 変更を記録する
> 差分を確認したので、担当県のファイルの変更だけをコミットして。何を記録したかと、確認する履歴を教えて。まだpushしないで。

確認：コミット履歴があるか。この時点ではGitHubにはまだ送っていません。

## 4. GitHubへ送ってPRを作る
> 現在の作業ブランチをGitHubへpushし、mainへのPRを作って。変更内容を簡潔に書き、PRのURLを教えて。まだマージしないで。

確認：GitHub上の差分、取り込み先main、変更ファイルが担当県だけであること。
PR作成をAIから実行できない場合は、支援者とGitHub画面で作成します。

## 5. チームで確認する
支援者や他のメンバーにPRを見てもらいます。担当県以外を変えていないかを確認します。
旅行内容の詳しい講評や、長いやり取りは必須ではありません。
締切までに全員のPRを提出できるよう、教え合ってください。

## 6. 共有版に集まったことを見る
マージ担当者が確認済みのPRを順次取り込みます。
GitHubのmainで、自分と他の人の旅行プランが入ったことを確認します。
時間があればAIにmainへ切り替えて更新を取り込むよう頼み、手元でも確認します。

## 用語と状態
- clone：共有リポジトリを履歴ごと手元へ持ってくる。
- ブランチ：共有版と分けて変更を進めるための分岐。
- 差分：変更前後でどこが変わったか。
- コミット：変更を説明付きで履歴に記録する。
- push：手元のコミットをGitHubへ送る。
- PR：変更をmainへ取り込むための提案。
- マージ：提案された変更を取り込む。
- pull：GitHub側の更新を手元へ取り込む。

保存・コミット・push・PR・マージは別の状態です。
